Welcome

Markedge PeopleOS is a multi-tenant People Operating System: one record per person, one configuration platform, one audit trail. This guide is for the people who run it day to day: tenant administrators, HR administrators, payroll administrators and managers. It follows the left-hand menu of the Admin Control Centre and tells you, for each area, what it is for, how to set it up and how the everyday tasks work.

Signing in

Open /admin in your browser and sign in with your work email and password. If your organisation has set up single sign-on you will also see a link such as /sso/<connection>/redirect; use it to sign in with your company identity provider. If your tenant requires multi-factor authentication you will be asked to pair an authenticator app on first sign-in and to keep the recovery codes somewhere safe.

Platform administrators (Markedge staff) sign in without a tenant and pick one under Platform → Tenants. A red "Exit tenant" item in the user menu returns them to the platform view. Tenant users never see other tenants.

Three habits that keep the system trustworthy

  • Give a reason. Most edit forms end with an "Audit reason" field. Write why you changed something; it is stored with the before-and-after values and cannot be deleted.
  • Use the actions, not the edit form, for state changes. Approving leave, finalising payroll, assigning an asset, completing an exit: these are buttons on the record page. They run the business rules, notify people and write the audit trail. Editing fields directly is reserved for correcting master data.
  • Configure in the Change Centre when the tenant requires approval. If the feature configuration.approval is on, medium- and high-risk configuration edits (policies, roles, settings, workflows, SSO…) are parked as proposals until a second person approves them.

Setting up a new tenant

A new tenant arrives with sensible defaults: system roles, a starter set of designations and employment types, leave types, salary components, a standard salary structure, ticket and grievance categories, letter templates, a five-point rating scale, competencies, asset categories, six shared reports and an HR overview dashboard. Work through this list in order.

  1. Organisation → Companies: create each legal entity with its legal name, country and currency. Every employee belongs to a company through their position, and payroll runs per company.
  2. Organisation → Organisation Designer: build the tree: company → business unit → division / department → team, and locations. Units can be renamed, moved and retired later; every change is effective-dated.
  3. People Setup: review designations, levels, grades, job families, employment types, categories and work modes. Add what your organisation uses; retire what it does not.
  4. Access → Roles: check the system roles (Tenant Super Admin, HR Admin, HR Manager, HR Executive, Payroll Admin, Attendance Admin, Performance Admin, Asset Admin, Manager, Employee, Executive, Alumni, Auditor). Create custom roles if needed and give each person the least access that lets them do their job.
  5. Access → Users: create logins for administrators now; employee logins are created when you hire people (or by SSO / SCIM).
  6. Configuration → Settings: set the employee code prefix, leave year start month, notice period, payroll options, security and retention windows.
  7. Configuration → Features: switch features on or off for the tenant (configuration approval, AI assistants, the language model, sensitive-access auditing).
  8. Configuration → Packs & blueprints: apply a configuration pack (for example the IT Company pack) to load a complete starter policy set, or import a blueprint exported from another tenant.
  9. Attendance: create shifts, a work schedule, a holiday calendar, and (if you use devices) attendance devices.
  10. Policies: publish attendance, overtime and leave policies and assign them to employees with rules.
  11. Payroll → Statutory profiles: for each company set which statutes apply (EPF, ESI, professional tax state, LWF, TDS) and the registrations.
  12. People → Employees: hire employees, assign salaries, collect documents. Bulk import of employee history is not available yet; enter history through the Employee 360 tabs.
Configuration edits on governed objects are audited; when configuration approval is on they also need a second person. Plan who approves before you start.

Roles, users and permissions

Access is built from permission keys (resource.action, for example leave.approve). A role is a named set of keys; a user holds one or more roles. Wildcards such as payroll.* in the system role templates are expanded when the tenant is provisioned, so what you see on a role is always the concrete list.

Manage roles

  1. Open Access → Roles and choose New role (or edit an existing custom role; system roles are updated by the platform).
  2. Tick permissions by module. Hover a key for its description.
  3. Save with a reason. Role changes are high-risk configuration and may go to the Change Centre.
  4. Assign the role to people under Access → Users (a user can hold several roles; permissions add up).

Sensitive data

Bank details, statutory identifiers (PAN, Aadhaar reference, UAN, ESIC), salary and payslips are sensitive. Viewing them needs the sensitive permissions and every view is written to the audit trail with the purpose the viewer typed. Grievance cases are visible only to their handlers.

People: the Employee 360

The Employee 360 is the single record for a person: identity, employment, organisation, reporting, attendance, leave, payroll, performance, learning, assets, documents, requests, exit and alumni all hang off it, each as a tab.

Hire an employee

  1. Open People → Employees → New employee. The wizard collects person details, employment (joining date, work email, whether to create a login), the first position (company, location, department, designation, level, grade, employment type, work mode) and the reporting manager.
  2. On save the person is created, the employee code is generated from the prefix in Settings, the lifecycle starts at joined (then probation if the employment type has a probation period), and any onboarding template whose rules match starts automatically.
  3. Use the Assign position action for transfers, promotions and other changes: each creates a new effective-dated position row; history is never overwritten.

Lifecycle

The lifecycle state is changed with the Lifecycle action, never by editing the field. Allowed moves are configured (for example probation → confirmed, active → notice period); each move is audited with its effective date and reason, fires notifications and workflows, and updates the timeline. Reminders for probation ending, joining dates and document expiry are sent by the daily lifecycle job.

Onboarding, documents and verification

Onboarding templates and plans

Under Workflows → Onboarding templates define phases (pre-boarding, day one, first week, first month…) with tasks, owners (HR, manager, IT role or the employee) and due offsets. Templates can carry assignment rules so the right template starts by itself when someone is hired. Plans appear on the Employee 360 and tasks in each owner's Task inbox.

Documents and verification

Document types come from People Setup → Document types; mark the ones mandatory for onboarding and those that expire. Background verification cases are opened from the Employee 360 and receive results from the BGV provider through the API or manually.

Attendance

Attendance turns punches, shifts, holidays and policies into one processed record per employee per day.

Set-up

  1. Attendance → Shifts: fixed or flexible shifts with start/end, break, full- and half-day minutes, grace and overtime settings.
  2. Attendance → Work schedules: weekly patterns of shifts (Mon–Fri general, rotations). Assign schedules to employees by rule or individually with an effective date.
  3. Attendance → Holiday calendars: calendars with holidays; rules decide which calendar an employee follows.
  4. Attendance → Devices: register biometric or kiosk devices; each gets an API key to push punches.
  5. Policies: attendance and overtime policies (grace minutes, late/absent rules, overtime eligibility).

Every day

  • Punches arrive from devices, the web check-in on My Day, mobile or import. The nightly job processes yesterday; you can reprocess a range from the records page.
  • Open the Attendance → Exception centre each morning: missed punches, late marks, short hours, unexplained absences and overtime awaiting approval, with actions to regularise, approve or mark.
  • Employees request regularisations from My Day; managers approve under Attendance → Regularisations or the task inbox. Approving reprocesses the day.
  • Records for a month become locked once payroll is finalised for that period; reopen the payroll run to change them.

Leave

Leave types and policies

Leave → Leave types lists the kinds of leave (earned, casual, sick, maternity, paternity, bereavement, comp-off, restricted holidays, leave without pay). Entitlements are not on the type: they live on a leave policy under Policies, one row per type with days per year, accrual frequency, carry-forward, encashment, probation eligibility and half-day rules. Assign policies to groups of employees with rules; publish a new version to change entitlements from a date.

Balances and requests

  • Balances are derived from an append-only ledger (accruals, requests, cancellations, encashments, adjustments). The nightly accrual job posts what is due; year-end carries forward and lapses per policy.
  • Employees apply from My Day or the Leave tab; the system validates policy, balance, half-days, weekends and holidays and either approves directly or starts the approval workflow.
  • Managers approve or reject under Leave → Leave requests or the task inbox. Approved leave updates attendance automatically.
  • HR adjusts balances and handles encashment under Leave → Balances and Leave → Encashments, always with a note.

Payroll and compliance

Payroll follows a fixed pipeline with separation of duties: the person who prepares a run cannot approve it.

Set-up

  1. Payroll → Salary components: earnings, deductions and employer contributions with their properties (taxable, PF/ESI wages, part of CTC/gross, prorated for loss of pay). Formula components reference earlier components, e.g. basic * 0.50. Statutory lines (PF, ESI, PT, LWF, TDS) are produced by the compliance engine and cannot be edited.
  2. Payroll → Salary structures: the ordered set of components an employee is paid with. The provisioned Standard structure pays basic 40 % of CTC, HRA 50 % of basic, fixed conveyance and a balancing special allowance.
  3. Payroll → Statutory profiles: per company, which statutes apply, the PT and LWF states, whether PF is restricted to the wage ceiling, and registration numbers. Payroll → Statutory rules shows the versioned rates the platform maintains; you cannot change them.
  4. Assign salaries on the Employee 360 → Salary tab: structure, annual CTC, fixed monthly amounts for fixed components, effective date and reason.
  5. Ask employees to file Payroll → Tax declarations (regime and investments) and to record PAN and a primary bank account; the control room shows who is missing what.

Run payroll each month

  1. Open Payroll → Control room → Open payroll run, choose company and month.
  2. Add one-off items under Adjustments (bonus, reimbursements, deductions, manual loss-of-pay days).
  3. Calculate. Every employee gets an entry with lines and a basis for each amount; exceptions (no salary, no bank, PAN missing, negative net, attendance missing) are listed.
  4. Fix inputs and recalculate until no blocking exceptions remain, then Validate.
  5. A second person opens the run and Approves.
  6. Finalize: attendance for the month is locked, the period is closed, payslips are generated and employees are notified.
  7. Download the Bank file (CSV) for salary transfer, then Mark as paid with the date.
  8. If something was wrong: Reopen (finalised, unpaid runs only) with a reason; payslips are withdrawn, attendance unlocked.

Payroll Auditor

Payroll → Payroll Auditor scans a run for anomalies: duplicate bank accounts, large net-pay swings versus the previous month, unusual deductions, high loss of pay, missing PAN or bank, large salary revisions, employees who have already exited. Findings are indicators for review, never automatic changes.

Performance and talent

Set-up

  1. Performance → Rating scales: the five-point scale is provided; create others if needed and mark one as default.
  2. Performance → Competencies and Performance → KRA library: what people are rated on and the goal templates they can pick from.
  3. Performance → Cycles: period, scale, stages with dates (goal setting, self review, manager review, peer review, calibration, final), weights for goals versus competencies, the competencies rated, and who is eligible (rules).

Run a cycle

  1. Launch the cycle: one appraisal per eligible employee is created with self and manager reviews; goals in the cycle lock when reviewing starts.
  2. Employees keep goals current with Check in on Goals; managers can add peer or upward reviewers on an appraisal.
  3. Move the cycle through its stages with Move to …; each stage notifies the people who must act.
  4. At calibration, use the Performance → Calibration board to see the rating distribution and calibrate or finalise inline. Finalising sets the label, records promotion or improvement-plan recommendations and notifies the employee, who acknowledges.
  5. Close the cycle when every appraisal is final; cycle goals complete automatically.

Continuous performance

  • Performance → Feedback: praise, constructive notes and feedback requests with visibility (private, manager, public).
  • Performance → One-on-ones: scheduled check-ins with agenda, private notes and action items.
  • Performance → Improvement plans: PIPs with objectives, extension and outcome; sensitive.
  • Performance → Career paths and the Performance → Career passport: ladders of designations with required skills; the passport shows each person's skills, credentials, history, aspirations and the gap to the next step.

Learning and assets

Learning

  • Learning → Courses: typed courses (video, document, e-learning link, classroom, virtual, assessment) with modules and an optional quiz whose answers stay hidden from learners; mark compliance courses mandatory and set certificate validity.
  • Learning → Learning paths: ordered course bundles.
  • Learning → Assignments: who must learn what by when, one person or a rule-defined audience, optionally recurring (annual PoSH refreshers). "Apply now" enrols immediately; the daily job keeps enrolling people who match later and marks overdue items.
  • Learning → Training sessions: classroom or virtual dates with capacity; employees register themselves; marking attendance completes the enrolment.
  • Learning → Enrolments and Learning → Certificates: progress, scores, expiry.

Assets

  • Assets → Categories and Assets → Models: laptop, monitor, mobile, SIM, ID card, access card, licence, vehicle, equipment…; mark IT assets and whether a serial number is required.
  • Assets → Asset register → Receive asset to add stock, then on the asset page use Assign, Transfer, Take back, Send for repair, Back from repair, Change location, Report lost, Found, Retire, Dispose. Every step is recorded in the Lifecycle tab; assigned assets cannot be disposed of.
  • Employees see My assets and acknowledge receipt. Active custody becomes the asset clearance checklist when someone exits.

Service desk, grievances, knowledge, communication

HR service desk

  • Service Desk → Categories & SLAs: request types with resolution and first-response hours, a default agent or agent role, an escalation role and an optional workflow (for example an approval flow for letters).
  • Employees use Ask HR on My Day; agents work the Tickets queue: reply (internal notes are hidden from the employee), wait on the employee, resolve with a linked knowledge article, close. Employees rate closed tickets and can reopen.
  • Breached SLAs escalate once to the escalation role; resolved tickets close automatically after five days.

Grievances

  • Grievances → Categories & handlers: confidentiality, whether anonymous cases are allowed, the handler roles (for example an Internal Committee role for PoSH) and the resolution SLA.
  • Cases are visible only to the assigned handler, users explicitly granted access, holders of the handler roles and, for named cases, the employee. Every view is audited.
  • Work a case with the case file (notes, evidence, actions, decisions; each entry marked visible to the employee or not), status updates, resolve and close. Employees can withdraw their own case.

Knowledge base and announcements

  • Knowledge → Articles: markdown articles by category with an audience rule, "requires acknowledgement" and "mandatory reading". Publishing creates a version; a new version asks everyone to acknowledge again. Read and acknowledgement counts are shown per article.
  • Communication → Announcements: announcements, circulars, newsletters, policy publications and instructions with audience, pinning, scheduling, expiry and acknowledgement. Employees read them on the Announcements feed.
  • Communication → Notification templates / rules: which events send which template on which channels (in-app, email, log) to which audience.

Exit, letters and alumni

Exit management

  1. Employees resign from My Day (Resign); HR initiates other exit types under Exit → Exit cases → Initiate exit (resignation, termination, retirement, contract expiry, absconding, death, mutual, other). Notice and last working day are computed from Settings and can be overridden.
  2. Five clearance stages are created: manager, IT, finance, asset, HR. Owners are the manager and the roles named in Settings. The asset stage lists everything in the person's custody and cannot be cleared while assets remain unless a recoverable amount is recorded. Clearance starts automatically seven days before the last day, or with Start clearance.
  3. The Full & final tab computes the last month's salary through the payroll calculator, leave encashment, notice shortfall recovery and asset recovery; add manual lines; approve (encashment posts to the leave ledger); mark paid.
  4. Record the exit interview (the employee can fill it themselves); Exit insights aggregates reasons and ratings.
  5. Complete exit once every stage is cleared and the settlement approved: the employee becomes exited and the login is suspended.
  6. Create alumni profile: the login is re-enabled with only the Alumni role; the person can use the Alumni portal to request letters, certificates and references.

Letters

Letters → Templates hold subject and body with variables such as {{ employee.name }}, {{ employee.designation }}, {{ employee.joining_date }}, {{ company.name }}. Generate a letter from an exit case, an alumni request or Letters → Letters → Generate letter; templates flagged for approval wait for someone with the issue permission; Issue stores it in the employee's documents and notifies them.

Alumni

Alumni → Alumni lists former employees with rehire eligibility and portal access. Requests arrive from the portal: verify identity, Approve & generate (letters are produced and issued automatically), mark delivered or reject.

Analytics

Dashboards

Analytics → Dashboards shows the boards you are entitled to; the provisioned HR overview is the default. Administrators design boards under Analytics → Dashboard builder: choose the audience roles and add widgets: KPI numbers, twelve-month trends, charts or tables from shared reports, leaderboards and a Needs Attention list.

Report builder

  1. Analytics → Reports → New report. Pick a dataset (employees, attendance, leave, payroll, exits, performance, learning, assets, service desk); you only see datasets your permissions allow, and sensitive fields such as CTC only with the sensitive permission.
  2. Tick the fields, add filters (equals, any of, contains, greater than, between, last N days, this month…), optionally group by a field with count / sum / average / min / max, add calculated fields with formulas such as employer_cost / paid_days, choose table, bar, line, pie or single number, and a sort and row limit.
  3. Open the report to run it; Export CSV (Excel-compatible) is audited. Add Schedules (daily, weekly, monthly) with recipients; each run is kept under Runs for download.
  4. Mark a report shared to make it available to dashboards, the API and other users who can see its dataset.

Command centre and intelligence

Analytics → Workforce Command Centre (executives) shows headcount, people cost, attrition, absenteeism, joiners and exits, high performers, cost per head, tenure, gender share, learning completion, open grievances, twelve-month trends and critical skills. Analytics → Workforce Intelligence lists attrition-risk signals per employee: transparent points (short tenure, no pay revision, low rating, overdue learning, no one-on-one, absences, constructive feedback, stalled high performer, open grievance). It is an inference to start conversations, never grounds for a decision.

Governance

  • Assistants never change records; they link to the page where a person acts.
  • Every question and answer is logged with its sources under Audit → AI interactions; users rate answers with thumbs up or down.
  • Answers are deterministic by default. Turning on the feature ai.llm (and configuring a provider) lets a language model rephrase the same facts; identifiers are redacted and the system falls back to the deterministic answer if the model is unavailable.
  • Anything marked inference (risk signals, audit findings) is an indicator, not a decision.

Configuration platform

Custom fields and forms

Customisation → Custom fields adds typed fields (text, number, date, yes/no, dropdown, multi-select, email, phone, URL) to employees, companies, departments, locations, designations and assets with visibility flags. Customisation → Forms builds versioned forms whose submissions can start workflows.

Policies and rules

Policies is the policy engine: policies of configurable types (attendance, overtime, leave, probation…) with versioned settings and effective dates, assigned to employees by rules (conditions on company, location, department, designation, level, grade, employment type, category, lifecycle state and more). The engine resolves the right version for each person on each date; modules read policy settings rather than hard-coding them.

Workflows and notifications

  • Workflows → Workflows: versioned definitions of start, approval (single, sequential, parallel, majority), condition, task, notification, wait, webhook, update-record, document and end nodes, triggered manually or by events (employee joined, leave requested, ticket created, exit initiated…). Publish a version to make it live; running instances and their tasks are visible, and the Task inbox is where approvers act. Escalations run every five minutes.
  • Communication → Notification rules: event → audience → channels → template, with variables like {{ employee.name }}.

Change Centre, packs and blueprints

  • Configuration → Configuration change centre: proposed configuration changes with impact preview, approval, scheduling for a future date and rollback. When the approval feature is off, edits apply immediately but are still audited.
  • Configuration → Packs & blueprints: export a tenant's configuration as a blueprint, import one, or apply a packaged starter set.
  • Configuration → Settings and Configuration → Features: tenant-wide values and switches (see the appendix).
  • Configuration → What do you want to configure?: type a word ("working hours", "designation", "pf") to jump to the right page.

Enterprise: integrations, SSO, security, international

Integrations and API

  • Integrations → API keys: issue keys with scopes (recruitment, verification results, attendance punches, and read scopes for employees, attendance, leave, payroll, documents, assets, performance, workflows, report runs, SCIM). The secret is shown once. Keys are sent as X-Api-Key or a Bearer token.
  • Enterprise → Webhooks: endpoints subscribed to events (leave approved, payroll finalized, exit initiated…). Deliveries are signed (HMAC-SHA256), retried with back-off, and listed with payload and response; "Send test" pings the endpoint.

Single sign-on and provisioning

  • Enterprise → Single sign-on: add a connection (Microsoft Entra ID, Google Workspace, Okta or generic OpenID Connect), paste client id and secret, adjust the endpoints from the preset, restrict email domains, choose whether first-time users are created automatically and with which role. Share the login URL shown in the list.
  • SCIM 2.0: issue an API key with the scim scope and configure your identity provider with the base URL /api/scim/v2. Users are created, updated and deactivated from the directory; a new login is linked to an existing employee by employee number or work email.

Security policy

Enterprise → Security policy: IP allowlist (exact addresses, wildcards, CIDR), require multi-factor authentication for every tenant login, sign out after idle minutes, minimum password length and expiry, and retention windows for AI interactions, notification deliveries and report runs. Audit events are never purged. Platform administrators are exempt from the allowlist.

International

  • Enterprise → Country packs: the countries the platform describes (currency, locale, tax framework, social security, labour rules, documents, formats). Set a company's country and the statutory profile's jurisdiction; India uses the full statutory engine, other countries the generic one with the rules their pack supplies.
  • Enterprise → Exchange rates: dated rates for consolidated reporting in the tenant base currency.

Audit, scheduled jobs and troubleshooting

Audit → Audit trail records who did what, when, from where, with before-and-after values, the reason, the approval reference and the effective date. Events are hash-chained per tenant; run Verify (or the console command) to prove nothing was altered. Sensitive views, configuration changes, payroll steps, exports and AI inference answers all appear here. Filter by module, actor, entity or date; every record page also has an Audit history tab.

Troubleshooting

SymptomCheck
A user cannot see a menu itemTheir roles under Access → Users; the permission key on the role; the feature switch under Configuration → Features.
An employee has no leave balanceA leave policy with that type must be published and assigned by a rule that matches the employee; then wait for the accrual job or accrue manually.
Payroll shows "no salary assignment"Assign a salary on the Employee 360 → Salary tab with an effective date inside the period.
Attendance for a day cannot be changedThe month is locked by a finalized payroll run; reopen the run first.
A configuration edit "went to the Change Centre"Configuration approval is on; a second administrator approves it there.
Nobody can open a grievance caseSet handler roles on the category, or grant access on the case.
A webhook keeps failingOpen the delivery, read the response excerpt, check the endpoint accepts POST with JSON and returns 2xx; retry from the list.
SSO login returns to the login pageRedirect URI registered with the provider must match /sso/<slug>/callback; the email domain must be allowed; auto-provisioning or an existing user is needed.
